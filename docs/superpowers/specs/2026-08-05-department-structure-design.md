# 组织架构部门收敛设计

## 目标

员工信息中的部门必须以 `O-Chart-20260727.pdf` 为主要依据，去掉中英文重复和空部门噪声，把研发、客户运营、运营、职能团队细分到实际叶子部门。页面默认只展示有在职员工的部门，且不显示内部公司缩写后缀。

## 数据原则

1. 组织架构中明确列名的员工，按图中叶子团队归属。
2. 组织架构发布日期后新增员工，按职位关键词、直接汇报人与已确认团队补位；无法唯一判断时保留当前有效部门，不猜测。
3. 演示员工218、演示员工243、演示员工247、演示员工209归 AI部；算法和软件各自独立。
4. 研发拆分：知识产权部、机械部、电气部、工艺部、光学部、算法部、软件部、测试部、系统工程部。
5. 客户运营拆分：销售部、应用部、现场服务部。
6. 运营拆分：制造部、仓库部、采购部、物控部、AI部。
7. 职能拆分：总经办、人事行政部、财务部、项目申报部、IT部。
8. 历史空部门和英文重复部门不删除，避免破坏历史引用；业务 API 与员工页面仅返回在职员工实际使用的正式部门。
9. 所有数据变更只在 `rayher.localhost` 本地 Docker 站点执行。

## 页面设计

员工表上方增加四个板块的部门卡片：客户运营、研发、运营、职能。每个板块只列实际有人部门和人数；点击部门即应用同一个部门筛选，当前选中项高亮。保留公司、部门和关键词筛选以及固定每页 20 人。表头和首列继续冻结。

## 后端接口

`get_dept_options()` 返回正式部门列表和在职人数，不再把底层所有 Department 主数据直接暴露给页面。返回项包含 `name`、`department_name`、`group_name`、`employee_count`。新增纯函数映射模块作为导入、同步脚本和测试的共同事实源。

## 迁移与回滚

同步函数先确保每家公司需要的正式部门存在，再按姓名更新在职员工部门。每次更新输出姓名、原部门、新部门；事务失败全部回滚。历史部门记录不删除。回滚时可用同步前导出的姓名-部门快照恢复。
