# QIHENG Demo Account And Project Access Fixes Design

**Date:** 2026-07-17
**Status:** Approved in conversation

## Scope

This change completes five related fixes without changing the three-level permission model: Admin, Project Owner, and Employee.

1. Rename active R&D employee login names to lowercase full-name pinyin at @rayher.local.
2. Add an in-app password change dialog.
3. Give Zhang Jun account-linked access to every project and the foreign commissioned R&D page.
4. Let authorized users open the private project initiation, completion, and capitalization confirmation files.
5. Allow zero hours only for activity types 请假 and 调休.

## Account Identity

The existing HR-EMP-xxxxx values are Frappe Employee document IDs generated by the HR-EMP- naming series; they are not user-selected login names.

Active R&D employee usernames will use full pinyin without separators, for example person070@legacy.example.invalid. If two employees produce the same pinyin, append the last four digits of the Employee ID. User rename must preserve the existing password, Employee user_id, Project project_owner, roles, and other Link references. The delivered account workbook will be regenerated with the renamed usernames and unchanged temporary passwords, then every username/password pair will be authenticated in a verification script without printing passwords.

## Permission Model

No fourth permission level is introduced.

- Admin can manage and read all projects and all project reports.
- A normal Project Owner can list, read, edit within the existing limits, and download reports only for projects whose project_owner equals the current User.
- Zhang Jun remains a Project Owner. The existing All Project Access capability attached only to his account is an exception marker, not a hierarchy level. It grants all-project visibility and foreign commissioned R&D access.
- Employees cannot access project management.
- Frontend route checks and backend API checks must apply the same rules.

## Project Report Files

The existing reports remain private files. Private means unauthenticated users and unrelated employees cannot open a copied URL; it does not prevent an authorized project owner from viewing the report.

The current direct /private/files/... links fail because the custom project API grants scoped access while Frappe's native File download check requires native Project permission. A whitelisted project-report download endpoint will:

1. accept only a Project name and one of the three allowed report field names;
2. run the same project scope check used by list_projects;
3. verify that the File record is attached to that Project and field;
4. stream the file as a download without exposing arbitrary filesystem paths.

The Projects page will use this endpoint for its three report actions. Missing source reports remain shown as not uploaded. Existing private files are not made public and are not duplicated.

## Password Change

The application header will expose 修改密码. A modal asks for current password, new password, and confirmation, then calls Frappe's stock frappe.core.doctype.user.user.update_password endpoint. Password values are never logged or persisted in frontend state after the dialog closes.

## Zero-Hour Leave And Comp Time

请假 and 调休 may be saved with 0 hours. Other activity types still require a positive value.

Because submitted ERPNext Timesheets reject zero-hour rows, an SPA-managed zero-hour leave/comp record is kept as a draft Timesheet marker. The entry list includes only these explicitly marked zero-hour drafts; allocation and cost reports continue to use submitted positive-hour Timesheets, so zero-hour markers never affect project ratios or costs. Updating or deleting the marker follows the same project and employee access checks as normal entries.
