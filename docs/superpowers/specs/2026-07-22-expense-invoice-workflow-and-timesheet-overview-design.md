# 费用报销发票汇总、手工无票费用与研发工时总览设计

日期：2026-07-22
状态：已获业务确认，待实施
分支：feat/ocr-monthly-timesheet-integration

## 1. 背景

费用报销流程已经具备发票批量上传、本地 OCR 七字段识别、人工确认、查重、下推报销草稿、查看发票、撤回、费用统计和审批记录能力。当前业务希望在不破坏既有数据和审批流程的前提下，完成：

1. 报销草稿按项目名称汇总发票费用。
2. 在项目名称后新增可选择也可填写的费用项目。
3. 草稿允许手工增加出差津贴等无票费用。
4. 只有一个金额的铁路等票据，将金额归入合计金额（税后金额）。
5. 调整发票下推弹窗的分类、字段名称和排列。
6. 优化上传发票工作台的视觉层级与响应式布局。
7. 恢复研发工时填报中的全部员工总览。

本次不包含发票真伪验证，也不处理加密文件白名单策略。

## 2. 已确认的业务口径

### 2.1 项目汇总

- 只按项目名称汇总，不把费用项目作为分组条件。
- 项目名称相同的发票，在报销草稿和详情中显示为一条汇总费用。
- 项目名称为空的发票不互相合并，每张保留独立待确认行。
- 用户补填相同项目名称并保存后，系统重新汇总。
- 每张原始发票仍可单独查看和撤回。
- 撤回部分发票后，系统重算该项目汇总金额；只有没有任何剩余来源时才移除汇总行。

### 2.2 单一金额

当 OCR 证据中只有一个有效金额，且没有税前金额或税额标签时：

- 填入合计金额（税后金额）。
- 税前金额与税额保持为空。
- 不通过金额相等或税额为零推断，避免误改正常零税率发票。

### 2.3 无票费用

草稿状态允许手工新增费用，字段包括：

- 项目名称
- 费用项目
- 费用日期
- 合计金额（税后金额）
- 费用说明
- 无票原因

无票行的发票类别、发票号码、税前金额和税额为空。项目名称相同的手工费用参与同一项目汇总。

### 2.4 申请人与支付字段

- 下推弹窗中的部门主管改为申请人。
- 申请人默认当前登录人并只读。
- 审批主管继续由后台审批路由自动解析，不由申请人填写。
- 付款类型改为支付个人、对公支付。
- 付款方式的界面名称改为支付方式。
- 排列顺序为：主题与公司、申请部门与申请人、付款类型与支付方式、收款人与开户行、支行与收款账号、备注。

## 3. 方案选择

比较过三种方式：

1. 仅前端临时合并：改动小，但统计、导出和撤回容易出现口径差异。
2. 删除原始行并只保存汇总行：界面简单，但会损失逐张发票和手工费用的可追溯性。
3. 服务端保留来源明细，同时输出统一的项目汇总视图：既满足汇总展示，又保留每张来源和撤回能力。

采用方案 3。汇总不是浏览器自行相加。后端负责分组、金额计算、更新和校验；前端、审批详情、统计和导出都消费同一服务端汇总结果。数据库保留来源级明细作为审计依据。

## 4. 数据模型

### 4.1 费用来源明细

在 OA Approval Expense Line 增加：

- expense_item：Data，费用项目。
- no_invoice_reason：Small Text，手工无票原因。

原有 line_key 继续作为来源明细的稳定标识。发票记录继续通过 request 与 expense_line_key 关联对应来源明细，避免更改既有 OCR 数据的归属。

source_invoice 保留用于兼容现有数据，但关联关系的校验以发票记录的 request 和 expense_line_key 为准。

### 4.2 服务端汇总对象

服务端为每张报销草稿生成 project_groups：

- group_key
- project_name
- expense_item
- invoice_categories
- issue_dates
- invoice_numbers
- amount_before_tax
- tax_amount
- total_amount
- source_line_keys
- invoices
- manual_source_count
- needs_project_name
- needs_expense_item

分组规则：

- 非空项目名称按去除首尾空格后的精确文本分组。
- 空项目名称使用各自 line_key 作为独立组。
- 同一项目的税前金额、税额、合计金额分别求和；空值不自动改成零参与字段展示。
- 多值发票类别、日期和号码在主表显示共 N 张，展开后显示逐张值。
- 费用项目若来源值一致则显示该值；不一致或为空时标记待确认。用户确认汇总组费用项目时，后端同步更新该组所有来源行。

### 4.3 手工来源

手工增加产生独立来源行，不伪造发票号码或附件。来源行保存费用日期、金额、说明和无票原因。服务端随后按项目名称把它纳入 project_groups。

## 5. 接口行为

### 5.1 发票下推

push_invoices_to_request 创建草稿时仍为每张发票创建可审计来源行，再由服务端生成项目汇总结果。每张发票都保留独立 expense_line_key。

### 5.2 草稿编辑

新增草稿更新接口支持：

- 修改项目名称。
- 修改费用项目。
- 新增、修改和删除手工无票来源。
- 保存后重建项目汇总。
- 重新计算申请单总金额。
- 同步人工修改的发票项目名称回发票记录，保证上传页、报销草稿和统计口径一致。

只有草稿状态和具备编辑权限的用户可操作。已提交、审批中、已通过或已付款单据不可直接修改费用来源。

### 5.3 撤回

撤回单张或部分发票时：

1. 只解除被选发票与来源行的关联。
2. 删除对应来源行。
3. 保留同项目其他发票和手工来源。
4. 重算汇总与申请单总额。
5. 写入操作记录。

### 5.4 校验

提交审批前校验：

- 所有汇总组必须有项目名称。
- 所有汇总组必须有费用项目。
- 手工行必须有正数合计金额与无票原因。
- 发票金额与来源金额差异沿用现有差异说明规则。
- 申请单总额必须等于所有来源行合计金额。

## 6. 前端交互

### 6.1 报销草稿详情

费用明细列为：

发票类别、项目名称、费用项目、开票日期、发票号码、税前金额、税额、合计金额（税后金额）、发票文件。

- 项目名称与费用项目在草稿中可编辑。
- 费用项目使用可输入组合框，建议项复用现有费用分类清单，同时允许自由填写。
- 同一汇总组的发票文件区域显示查看发票 1、查看发票 2 等入口。
- 明细下方增加手动增加费用按钮。
- 手工费用以无票标识显示。
- 原有付款信息、审批记录、操作记录、撤回和提交按钮继续保留。

### 6.2 下推弹窗

- 申请人为当前登录人，只读显示。
- 付款类型选项为支付个人、对公支付。
- 标签改为支付方式。
- 字段按已确认顺序重新排列。
- 后端兼容历史付款申请值，读取旧单时映射显示为支付个人，但不批量改写历史记录。

### 6.3 上传发票工作台

现有页面的问题来自固定宽度表格与右侧表单同时占用空间，导致中等分辨率下列被压缩、空白分布不均、主要操作与状态分散。

改造原则：

- 保持发票总数、待确认、已确认、已下推、疑似重复指标。
- 统一卡片高度、边距、状态颜色和按钮层级。
- 宽屏使用列表和确认面板双栏，确认面板保持合理宽度并可在内部滚动。
- 中等与小屏改为上下布局，不依赖页面级横向滚动。
- 表格优先展示文件、状态、项目名称、发票号码、合计金额；其余字段在确认面板完整展示。
- 上传、刷新、确认、预览、下推和撤回入口位置固定且清晰。
- 保留现有安全预览、水印、查重和权限控制。

## 7. 费用统计与审批记录

- 费用统计增加费用项目筛选和列。
- 统计来源使用服务端统一汇总口径。
- 手工无票费用计入申请金额、已付与未付金额。
- 审批记录与操作记录结构不变。
- 导出结果增加费用项目与无票原因，项目汇总金额与页面一致。

## 8. 研发工时全部员工总览

### 8.1 根因

月度工时页面替换旧按日页面时，旧页面中的全部员工选择器和概览区域被删除。后台月度接口 list_monthly_entries 已支持 employee 为空并按照当前用户权限返回全部可见员工，员工数据没有丢失。

### 8.2 恢复方式

- 研发人员选择器重新加入全部员工选项。
- 对具备多员工查看权限的账号，默认进入全部员工。
- 全部员工模式为只读总览，表格增加研发人员列，并显示当月总发生天数、总工时及员工人数。
- 选择单个员工后恢复现有按月编辑、Excel 导入、保存和删除能力。
- 普通员工仍只能看到本人；部门主管只能看到本人和直属员工；系统、HR、财务等现有授权角色按原权限查看全部可见人员。
- 前端不得在全部员工模式调用保存接口，后台保存接口仍强制要求明确 employee，形成双重保护。

## 9. 兼容与迁移

- 只新增字段，不删除或重命名现有数据库字段。
- 新字段默认空，不批量修改旧报销单。
- 旧付款申请值保留并在界面兼容映射。
- 现有 OCR 发票、附件、查重状态、报销关联和审批记录保持原样。
- 新增汇总由读取时计算，不需要危险的数据重写。
- 部署前备份当前应用文件和站点数据库。
- 构建产物通过现有清单部署，部署后校验文件哈希和站点健康状态。

## 10. 测试与验收

### 10.1 后端

- 同项目两张发票形成一组且金额正确。
- 不同项目保持多组。
- 空项目名称每张独立，补填后合并。
- 同项目多张发票均可预览。
- 撤回其中一张后保留其余来源并重算。
- 手工无票费用新增、编辑、删除及必填校验。
- 发票与手工费用同项目时正确汇总。
- 单一金额只进入合计金额。
- 正常含税、零税率票据不被错误清空。
- 权限、审批状态与付款状态禁止越权编辑。
- 旧数据序列化和统计兼容。
- 月度工时全部员工查询遵守可见范围。

### 10.2 前端

- 费用项目可选择和自由填写。
- 手动增加费用按钮仅在可编辑草稿出现。
- 下推弹窗字段、选项、顺序正确。
- 上传工作台在 1366、1920 和 2560 宽度下无页面级横向溢出。
- 发票预览可正常打开关闭。
- 全部员工工时总览只读，单员工模式可编辑。
- 原有费用统计、审批记录、撤回、下推和 OCR 回归测试通过。

- 管理账号能看到全部员工月度工时；普通员工不能越权查看。
- 两个业务页面 HTTP 正常，容器健康，既有 OCR 记录与原审批数据数量不减少。
