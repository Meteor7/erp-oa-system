# 账号凭据与发票下推收口设计

## 目标

本次变更同时处理四项已确认需求：

1. 交付当前 59 个启用 System User 的账号与可用临时密码。
2. 发票下推到费用报销流后，不再出现在“上传发票”工作区。
3. 发票报销默认付款给个人，同时保留对公支付场景。
4. 下推表单中的“总经理室”统一改为“总经办”。

## 账号与密码

- Frappe 仅保存不可逆密码哈希，无法读取既有明文密码。
- 保留 4 个近期创建账号的已知临时密码；其余 55 个启用 System User 重置为独立随机临时密码。
- 执行前创建数据库及私密文件备份，账号重置放在部署与验收之后执行，避免中途影响登录。
- 生成完整 CSV，包含账号、姓名、临时密码和是否本次重置；文件只进入私密交付目录，不进入 Git。
- CSV 和容器内副本限制访问权限，并在交付前检查文件为正常明文而非 TipRay TSD Header。

## 发票下推后的可见性与撤回

- `list_workbench` 后端默认排除已关联报销单的发票，前端上传工作区只展示仍需处理或待下推的发票。
- 已下推发票和附件不会删除，继续保留在报销单、审计日志和数据库中。
- 原上传页的“撤回下推”入口移到对应报销草稿详情。
- 审批中的报销需先“撤回申请”成为草稿，再执行“撤回下推”；撤回成功后解除发票与报销单关联，发票重新出现在上传工作区。
- 后端提供显式 `include_pushed` 兼容参数，便于受控查询历史记录，但上传页不启用。

## 付款类型

- 付款类型仍为“支付个人”“对公支付”两种。
- 发票报销下推和无票报销新建时默认选择“支付个人”，收款人默认当前申请人。
- 用户仍可在确属公司直接向供应商付款时手动选择“对公支付”。
- 对现存来源为发票下推、尚未付款且错误保存为“对公支付”的单据迁移为“支付个人”；已付款历史不修改。
- 前后端共同校验合法枚举，避免只改显示不改入库。

## 部门名称

- 后端选项将“总经理室”替换为“总经办”。
- 对输入和输出增加旧值兼容映射，旧数据统一显示为“总经办”。
- 尚未完成的报销单中旧部门值迁移为“总经办”；历史已付款记录保持原始审计值。

## 验证

- 后端单元测试覆盖默认隐藏、显式包含、撤回后重新出现、默认支付个人、旧部门兼容。
- 前端测试覆盖上传页无“已下推”卡片/按钮、报销草稿有撤回入口、默认付款类型和总经办选项。
- 执行后端全量测试、前端全量测试与生产构建。
- 部署到现有 Frappe 容器后，用浏览器验证上传、下推、隐藏、撤回、重新出现及下推表单。
