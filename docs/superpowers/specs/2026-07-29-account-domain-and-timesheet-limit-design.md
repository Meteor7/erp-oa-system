# QIHENG DEMO 账号域名迁移与月度工时上限设计

日期：2026-07-29

## 目标

1. 消除业务登录账号中的 QIHENG Demo 域名，将现有旧域账号迁移为 QIHENG DEMO 内部域名。
2. 在按月工时填报页面显示所选月份的工作日上限和对应小时数，并用同一口径进行前后端保存校验。
3. 保留既有密码、角色、Employee 关联、审批关系及历史单据引用，避免迁移后无法登录或审批任务丢失。

## 范围

### 账号迁移

以下账号进入迁移范围：

- 所有当前以 `@legacy.example.invalid` 结尾的 User，共 9 个。
- 管理账号 `admin@legacy-business.example.invalid`。

目标账号采用相同本地部分并统一改为 `@staff.example.invalid`。当前数据库检查显示 10 个目标 User ID 均无冲突。

现有 `@business.example.invalid` 账号保持不变。系统内置账号 `Administrator`、`Guest` 不变。站点内部名称 `rayher.localhost`、应用包名和数据库技术标识不属于员工登录账号，本次不改。

### 工时上限

按月工时填报页显示：

`本月上限：X 天 / Y 小时`

其中 `Y = X × 8`。本次只定义月度可填报上限，不调整员工请假、入离职日期或个人排班造成的个体差异。

## 账号迁移设计

### 迁移原则

使用 Frappe 的文档重命名能力迁移 User 主键，不直接更新单表。由框架更新 Link 字段和可识别的动态链接，保留账号密码哈希、角色、权限及审计关系。

迁移前必须：

1. 创建数据库与站点文件备份。
2. 生成旧账号到新账号的一一映射。
3. 再次检查目标账号不存在、旧账号存在且启用状态符合预期。
4. 记录 Employee.user_id、核心审批账号和待审批步骤的迁移前快照。

迁移顺序：

1. 依次重命名 9 个 `@legacy.example.invalid` User。
2. 将 `admin@legacy-business.example.invalid` 重命名为 `admin@staff.example.invalid`。
3. 对管理账号设置新的随机强密码；其他账号密码保持不变。
4. 更新代码中的正式账号配置、OA 路由常量、维护脚本和相关测试期望。
5. 执行补充迁移，修复存储在 JSON/文本字段内、无法由 Frappe Link 重命名自动更新的审批人列表和历史审批步骤。
6. 重新生成全体账号密码表、管理账号单表和按有效部门主管拆分的 8 份账号表。

测试中仅用于构造场景的 `person042@legacy.example.invalid`、`person054@legacy.example.invalid` 等虚拟地址可替换为中性示例域名；部署站点名、历史设计文档和技术运行手册不进行无意义批量改名。

### 密码处理

- User 重命名不重置现有 9 个账号的密码。
- 管理账号原密码不可逆读取，按用户授权生成并设置新密码。
- 密码只写入交付 Excel，不写入 Git、日志或测试输出。
- 登录验证脚本逐一验证账号密码但不得打印密码。

### 审批与组织引用

迁移后必须验证：

- 每个迁移账号仍与原 Employee 唯一关联。
- OA 核心审批人演示员工13、演示员工10、演示员工18、演示员工16、演示员工21、演示员工29仍能被路由诊断解析。
- 待审批和历史 OA Approval Step 中的 approvers、approved_by、paid_by 等字段不存在旧域账号。
- 组织主管解析结果与迁移前人员结构一致。

## 月度工时上限设计

### 工作日计算

计算优先级：

1. 选择具体员工时，优先使用员工关联的 Holiday List。
2. 员工未配置时，使用所属公司的 Default Holiday List。
3. “全部员工”视图使用公司 Default Holiday List。
4. 没有任何 Holiday List 时，回退为周一至周五，并在 API 返回 `calendar_source=weekday_fallback`，页面显示“使用默认工作日历”。

有 Holiday List 时，以所选月的全部自然日减去 Holiday List 中的假日记录。周末是否休息及调休上班日均由 Holiday List 决定；未列为假日的调休周六可以计入工作日。

API 返回：

- `day_limit`：工作日数量。
- `hour_limit`：`day_limit × 8`。
- `calendar_source`：`employee_holiday_list`、`company_holiday_list` 或 `weekday_fallback`。
- `holiday_list`：实际采用的假日表名称，无假日表时为空。

### 页面行为

在工时填报页顶部合计区显示：

- 当前已填：`A 天 / B 小时`。
- 本月上限：`X 天 / Y 小时`。
- 回退周一至周五时追加低干扰提示。

切换员工、年份或月份时重新加载上限。全部员工只读视图展示公司月度上限，但不把多名员工合计与单人上限比较。

### 校验

前端在保存前校验所选员工当月累计发生天数不超过 `day_limit`。后端重新计算同一员工和月份的上限并强制校验，不信任前端传值。Excel 导入和粘贴导入最终都经过同一后端校验。

原有“自然日上限”实现替换为“工作日上限”。每行仍按 `发生天数 × 8` 自动计算小时。

## 异常处理与回滚

- 任一目标账号冲突、Employee 关联不唯一或迁移前快照异常时停止，不进行部分迁移。
- 账号迁移在可控维护窗口执行；失败时利用账号映射反向重命名，必要时从迁移前数据库备份恢复。
- 管理账号新密码只在迁移成功后写入交付表。
- 假日表配置异常时不阻止页面读取，回退周一至周五并明确提示；保存校验使用同一回退口径。

## 验证标准

### 账号

- 10 个新域账号存在并启用，10 个旧域账号不存在。
- 9 个普通/审批账号使用原密码登录成功；管理账号使用新密码登录成功。
- Employee、角色、用户权限、项目权限和审批路由与迁移前一致。
- 数据库业务字段、当前审批步骤和交付 Excel 中不再出现 `@legacy.example.invalid` 或 `admin@legacy-business.example.invalid`。

### 工时

- 已配置假日表月份的工作日天数与表内假日计算一致。
- 调休工作日和法定节假日按 Holiday List 正确计入或排除。
- 无假日表时周一至周五结果正确并显示回退提示。
- 页面同时显示上限天数和小时数。
- 等于上限可保存，超过上限在前后端均被拒绝。
- 现有工时保存、导入、查看和导出功能测试通过。

## 非目标

- 不更改公司正式邮箱 `@business.example.invalid`。
- 不重命名 Docker 容器、Frappe app、Python 包、站点目录或 Git 仓库。
- 不在本次实现个人请假、入离职或不同班次对月度上限的动态扣减。
