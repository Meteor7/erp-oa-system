# 账号凭据与发票下推收口实施计划

> 对应设计：`docs/superpowers/specs/2026-07-23-account-credential-invoice-handoff-design.md`

## 1. 发票工作区契约

- 先为 `list_workbench_invoices` 增加失败测试：默认排除 `request` 非空记录，`include_pushed=1` 时允许受控返回。
- 修改 service、白名单 API 和前端 API 参数。
- 上传工作区移除已下推统计和上传页撤回按钮。

## 2. 报销单撤回下推

- 先增加前端源码/组件测试，要求草稿详情显示“撤回下推”。
- 在费用报销详情使用已加载的发票名称调用现有 `withdraw_invoice_push`。
- 成功后刷新报销单、发票明细和看板；审批中必须先撤回申请。

## 3. 付款类型与部门

- 先增加后端测试：付款类型默认“支付个人”，部门选项/旧值规范化为“总经办”。
- 增加部门显示及入库规范化，更新前端默认值。
- 编写幂等迁移脚本，只更新未付款发票报销及未付款旧部门值。

## 4. 账号重置与私密交付

- 备份站点数据库和私密文件。
- 编写带 dry-run 的维护脚本，读取所有启用 System User。
- 保留 4 个已知临时凭据，对其余账号生成独立强随机密码并设置。
- 输出 59 行私密 CSV；校验数量、唯一性、权限和明文头，禁止纳入 Git。

## 5. 验证与部署

- 执行针对性测试，再执行后端、前端全量测试与生产构建。
- 将校验过的源码和前端构建部署到 `rayher-bench`，清缓存并重启。
- 浏览器回归发票上传、确认、下推、隐藏、撤回、付款类型、总经办显示。
- 最后执行账号重置，使用新凭据验证演示员工170登录，再提交当前功能分支。
