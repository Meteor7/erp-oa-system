## 2. 变更摘要

近期改动围绕采购申请、物料主数据、审批顺序、采购资料与页面体验展开。

已完成的核心能力：

1. 采购需求审批顺序调整为“直属上级与项目主管会签在前，PMC 在后”。项目采购必须两人全部通过；非项目采购仅走直属上级；顶层主管保留跳过规则。
2. PMC 可以在审批上下文修改申请，系统记录修改人、时间、版本、修改前后差异和所在节点，并抄送申请人、直属上级和项目主管。
3. 物料分类与物料主数据改为动态数据库模型，支持任意层级，不把分类结构写死。
4. 已导入参考物料库，当前确认口径为 5,212 条物料、987 条分类、8 个顶级类别。
5. 员工端物料选择器改为单栏逐级筛选，五级分类加一段物料流水号形成完整六段编码。
6. 选择现有物料流水号后，自动回填物料名称、规格型号、产品描述、品牌、单位、属性等资料。
7. 找不到现有物料时，员工至少填写三级分类和完整需求信息，提交给 PMC 统一补全分类或新增物料，员工不直接生成正式物料编号。
8. 新增重复物料判断与智能分类建议，PMC 新增前可查看重复风险、相似物料及建议分类。
9. 采购申请新建页改为独立路由，并修复新建页被权限守卫错误跳转到数据看板的问题。
10. 修复采购明细保存时后端漏传 `business_lines`、前端提交界面状态字段导致格式错误、选择流水号后分类面板不自动收起等缺陷。
11. 采购资料清单改为按业务节点展示，移除了错误的“需求申请”待补资料项。
12. 采购付款审批人已按现岗位调整，演示员工110为演示员工32，不再使用已演示员工167员演示员工13。

尚未完成、需纳入本 PRD 的最新体验要求：

1. 员工误选物料流水号后，可清除正式物料关联，切换为“未找到物料，交由 PMC 新增”。
2. 审批操作和审批轨迹上移到详情首屏，不要求用户滚动到页面底部。
3. PMC 新增或修改物料改为独立内页，不在详情页底部展开长表单。
4. 审批成功后按钮立即消失或进入明确的已完成禁用态，防止用户误以为没有提交成功。
5. 继续压缩采购申请详情中占位过大的摘要区，提高采购明细、当前节点和关键动作的信息密度。

## 3. 背景与问题

原采购申请流程存在以下问题：

- PMC 位于直属上级和项目主管之前，无法先完成业务必要性审批再进行物料归档与补录。
- 员工与 PMC 的职责边界不清，员工页面曾出现物料目录维护入口，容易造成同一物料被不同人员重复建码。
- 采购申请只有简单文本明细，缺少与正式物料库的分类、流水号、规格和品牌关联。
- 物料分类选择器曾拆成多个栏目，层级多、占位大，且末级分类后无法继续选择物料流水号。
- PMC 修改、审批动作、审批轨迹、业务资料散落在长页面底部，操作成本高。
- 审批成功后按钮仍保留，缺少即时状态反馈。
- 业务资料清单曾把申请本身错误识别为“需求申请”附件，形成无效待补项。
- 本地构建曾受 TipRay 透明加密影响，出现源码已改但运行页仍加载旧资源的问题。

## 4. 产品目标

### 4.1 业务目标

- 明确员工、业务审批人、PMC、采购经办人、财务岗位的职责边界。
- 由 PMC 统一维护正式物料分类与编码，减少重复物料和错误分类。
- 将需求审批、采购执行、价格审批、演示员工116、到货、验收、付款串成可追踪的完整链路。
- 保证审批中的修改有版本、有差异、有抄送，不破坏已经完成的上游审批记录。

### 4.2 体验目标

- 员工可以在一个物料栏内完成搜索、逐级筛选、选择流水号或转为 PMC 补录。
- 审批人进入详情首屏即可看到当前节点、关键申请信息、审批动作和审批轨迹。
- PMC 从独立内页完成补录或修改，避免在长详情页底部操作。
- 所有关键提交动作都有明确的加载、成功、失败和已完成反馈。

### 4.3 非目标

- 不在员工端开放正式物料编号生成权限。
- 不把分类层级固定为六级；六段编码只是当前参考库的常见结构。
- 不在本期实现与参考系统的持续双向同步或回写。
- 不在本 PRD 中安排 Staging / Product 发布。

## 6. 核心业务定义

### 6.1 物料编码

示例：`1.ELC.1.1.01.003`

- `1.ELC.1.1.01`：五级分类路径。
- `003`：该分类下的物料流水号。
- 完整编码共六段，但最后一段是物料，不是分类。
- 数据模型必须支持任意层级分类，以兼容新增类别和未来扩展。

### 6.2 现有物料与新增物料需求

- 现有物料：员工选中正式流水号，系统回填完整主数据并保存快照。
- 新增物料需求：员工未找到匹配流水号，至少选择三级分类，填写名称、规格、描述、品牌、单位、数量、需求日期等，状态标记为“待 PMC 补录”。
- 正式新增：由 PMC 判断是否重复，补全分类并生成或录入正式物料编号。

## 7. 目标流程

### 7.1 采购需求审批

```text
员工提交采购申请
    ↓
直属上级 + 项目主管并行会签（仅项目采购，必须全部通过）
    ↓
生产设备负责人（仅生产设备类）
    ↓
PMC 审批 / 补录 / 修改
    ↓
演示员工21需求终审
    ↓
演示员工216采购询价、录入价格
    ↓
演示员工21价格审批
    ↓
演示员工116、付款计划、到货、验收、付款执行
```

非项目采购不经过项目主管。若直属上级属于系统定义的顶层主管，按既有规则跳过重复上级审批。

### 7.2 PMC 修改

1. PMC 从待办或采购详情进入“物料补录/修改”内页。
2. PMC 可绑定已有物料、补全分类、新增分类、新增物料或修正申请明细。
3. 保存时生成新版本，并记录修改人、时间、节点、原因（选填）、修改前后差异。
4. 系统抄送申请人、直属上级和项目主管。
5. 已完成的直属上级/项目主管审批不重置。
6. 后续需求终审基于 PMC 修改后的最新版本进行。

### 7.3 采购付款

采购付款审批顺序：

```text
演示员工21 → 演示员工19 → 演示员工16 → 演示员工32（演示员工110） → 演示员工29确认付款
```

不同付款阶段必须关联相应付款计划，并在到货、验收、发票条件满足后进入对应付款动作。

## 8. 功能需求

### FR-01 采购申请独立内页

- 新建采购申请使用独立路由，不嵌在申请列表底部。
- 从列表点击“新建申请”后必须进入采购申请页，不得因权限继承缺失跳回数据看板。
- 页面离开时，未保存内容需给出提示或保留草稿。

状态：已完成基础路由与权限修复；草稿离开保护需按现有行为复核。

### FR-02 单栏物料选择器

- 仅显示一个物料选择栏。
- 支持按分类编码、分类名称、物料编码、物料名称、规格型号、品牌进行包含搜索。
- 支持按 Enter 选择第一条匹配结果。
- 支持逐级进入分类，顶部展示当前路径并允许返回上一级。
- 到达末级分类后展示该分类直属物料流水号，不得提前关闭面板，也不得把全部后代物料铺在根节点。
- 选择流水号后自动关闭面板，并在同一栏显示完整编码与名称。

状态：已完成并实测 `1 → ELC → 1 → 1 → 01 → 003`。

### FR-03 现有物料回填

选择正式物料后自动回填并保存：

- 物料编码
- 分类编码与分类路径
- 物料名称
- 规格型号
- 产品描述
- 品牌
- 计量单位
- 物料属性
- 可选英文名称、英文描述、英文品牌

前端仅提交业务字段，不得提交 `category_parts`、搜索词、面板展开状态等界面状态字段。

状态：已完成。

### FR-04 从已选流水号切换为 PMC 新增

- 已选中正式物料后，必须提供“清除已选物料”动作。
- 清除后移除 `material_code` 关联，但保留员工已经填写且仍有价值的需求字段。
- 用户可继续选择至少三级分类，并明确标记“物料库未找到，交由 PMC 补录”。
- 再次选择现有流水号时，取消“待 PMC 补录”状态。
- 提交前页面明确显示当前模式：`已绑定现有物料` 或 `待 PMC 新增/补录`。

状态：待实现，P0。

### FR-05 员工新增物料需求

员工未找到现有物料时，提交至少需要：

- 至少三级分类，例如 `1.ELC.3`
- 物料名称
- 规格型号
- 产品描述
- 商品品牌
- 计量单位
- 数量
- 需求日期
- 用途/项目
- 备注（选填）

员工不能创建正式物料编号。提交后该明细进入 PMC 待补录队列，不阻塞需求申请本身进入审批。

状态：已完成基础校验与待 PMC 补录能力。

### FR-06 PMC 物料补录/修改内页

- PMC 功能与普通审批同级，入口来自 PMC 待办和采购详情。
- 使用独立内页，不在详情页底部展开长表单。
- 页面应同时展示员工原始需求、当前分类、相似物料、重复风险、智能分类建议和修改表单。
- PMC 可执行：绑定已有物料、修改分类、新增分类、新增正式物料、修改物料资料、修改需求明细。
- 保存前展示变更摘要；保存后生成版本并抄送相关人。

状态：后端能力和页内表单已存在；独立内页与入口整合待实现，P0。

### FR-07 重复判断与智能分类

- 名称、规格、品牌完全一致：高可信重复，优先建议绑定已有物料。
- 规格仅大小写、空格、连接符不同：高风险格式差异，必须人工确认。
- 仅名称相同：中低风险，继续核对规格、品牌和用途。
- 最多展示 3 个参考物料，并展示分类路径、相似度、风险等级和建议动作。
- 智能分类仅提供候选，不自动覆盖 PMC 已选择的分类。

状态：已完成后端建议与测试。

### FR-08 审批顺序与权限

- 项目采购的直属上级与项目主管使用 `all` 会签，必须全部通过。
- 非项目采购只经过直属上级。
- 生产设备类追加生产设备负责人节点。
- PMC 位于上游业务审批之后。
- PMC 后进入演示员工21需求终审，再进入采购询价和价格审批。
- PMC 修改不重置已经完成的上游审批，只抄送相关人。

状态：已完成。

### FR-09 审批操作与审批轨迹

- 详情首屏必须同时出现当前节点、审批操作和审批轨迹摘要。
- 审批按钮放在关键信息摘要之后、明细长表之前。
- 完整轨迹可展开查看，不要求用户滚动到页面底部。
- 点击审批后立即进入提交中状态，防止重复点击。
- 审批成功后刷新当前单据状态：无权限再次审批时隐藏按钮；若保留按钮，则必须禁用并显示“已通过”。
- 成功反馈必须包含当前动作结果和下一节点；失败时保留输入并显示可理解的错误信息。

状态：待实现，P0。

### FR-10 采购详情可视化

- 首屏优先展示：申请编号、主题、申请人、项目、当前节点、采购项数、总数量、关键状态和审批动作。
- 低信息量字段不得使用大面积独立区块。
- 采购明细在桌面端使用高密度表格；窄屏使用字段分组，避免横向裁剪和文本重叠。
- 需求审批阶段隐藏价格审批、演示员工116和付款计划入口。
- 进入采购执行或价格阶段后，才显示报价、价格审批、演示员工116和付款计划入口。

状态：已完成第一轮紧凑化和响应式布局；详情首屏与操作区仍需二次优化，P0。

### FR-11 业务资料清单

- 需求申请本身不是附件，不得显示为“待补充材料”。
- 报价/价格阶段显示报价单、价格审批表。
- 演示员工116阶段显示演示员工116、付款计划。
- 到货前要求送货单、收料单、入库单三选一。
- 验收通过前要求验收资料。
- 付款前是否要求发票，由付款计划的发票条件决定。
- 允许上传其他补充资料，所有上传、删除和版本变化必须留痕。

状态：已完成前端节点清单；关键动作的后端强校验按现有采购生命周期继续执行。

### FR-12 关键缺陷修复

- 保存采购草稿时必须把 `business_lines` 传入采购校验。
- 后端保存与提交必须使用同一套采购明细规则。
- 产品描述、规格、品牌、单位等必填规则不得因测试夹具缺字段而放宽。
- 物料选择器选中流水号后自动收起。
- 新建页继承采购申请访问权限。
- 运行环境必须加载最新构建产物，构建文件不得包含 TipRay TSD Header。

状态：已完成。

## 9. 数据与审计要求

### 9.1 采购明细快照

申请提交时保存物料主数据快照，至少包含编码、分类、名称、规格、描述、品牌、单位和属性。后续物料库修改不得无痕覆盖历史申请内容。

### 9.2 PMC 修改版本

每次修改保存：

- 申请编号
- 版本号
- 修改人及账号
- 修改时间
- 修改所在节点
- 修改原因（选填）
- 修改前值、修改后值、字段级差异
- 抄送对象与送达状态

### 9.3 物料主数据

- 分类和物料均使用数据库记录，不在前端写死。
- 分类编码唯一；物料编码唯一。
- 新增物料前必须执行重复判断。
- 参考库的一次性导入保留原编码和 8 个顶级类别。

## 11. 验收标准

### AC-01 物料选择与回填

1. 从一级分类逐步进入 `1.ELC.1.1.01`。
2. 页面只展示直属流水号 `.001` 至 `.005`。
3. 选择 `1.ELC.1.1.01.003` 后，回填“机柜 / ND-MB-800 / 完整描述 / 金盾 / 台”。
4. 面板自动收起，已选提示显示完整六段编码。

### AC-02 模式切换

1. 员工先选择任一正式流水号。
2. 点击清除后，正式编码为空，页面显示“待 PMC 补录”。
3. 保留员工已填写的需求资料。
4. 选择至少三级分类后可保存或提交。
5. 再选正式流水号时恢复为“已绑定现有物料”。

### AC-03 采购审批

1. 项目采购同时生成直属上级与项目主管会签任务。
2. 任一人未审批时不得进入 PMC。
3. 两人全部通过后进入 PMC。
4. PMC 修改后生成新版本并抄送申请人、直属上级、项目主管。
5. 上游审批不重置，演示员工21基于新版本需求终审。

### AC-04 审批反馈

1. 审批操作在首屏可见。
2. 点击后按钮立即禁用并显示提交中。
3. 成功后按钮隐藏或显示“已通过”禁用态。
4. 审批轨迹无需滚动到底部即可看到新增记录。
5. 页面明确显示下一节点。

### AC-05 PMC 内页

1. PMC 从待办进入独立补录页。
2. 页面展示原始需求、现有关联、重复建议和修改表单。
3. 可绑定已有物料，也可新增分类和物料。
4. 保存后返回采购详情，并显示最新版本与修改摘要。

### AC-06 资料清单

1. 需求审批阶段不显示“需求申请”待补资料。
2. 当前节点缺少 0 项时不得显示错误警告。
3. 到货、验收、付款阶段分别展示对应资料要求。
4. 发票要求服从付款计划中的发票条件。

## 14. 风险与约束

- TipRay 透明加密可能让 Docker 读取到 TSD 密文，所有构建和交付文件必须做明文头校验。
- 当前工作区包含大量未提交改动和构建产物，实施时必须避免覆盖无关用户修改。
- 参考物料库的一次性导入已满足当前需求；若要持续同步，需要正式接口、源码或数据库导出支持。
- 历史采购申请必须保留物料快照，不能因主数据更新改变历史审批依据。
- PMC 修改不重置上游审批属于已确认业务规则，必须依赖版本和抄送保证可追溯性。
